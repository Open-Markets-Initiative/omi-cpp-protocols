# Flyweight C++ Views

Views over the wire's bytes, read in place: a view holds a span of bytes it does not own,
and each accessor reads its member where it lies, when it is asked. Nothing is decoded up
front and nothing is copied. Unlike the Advanced parsers nothing is laid over the bytes:
every value is copied out of its bytes and swapped to the host's byte order, so there is no
`#pragma pack` and no alignment or aliasing to rely on, and a view reads the same on every
compiler and host. Text is a `std::string_view` of its bytes, bytes a `std::span`, and a
composite or bitfield a view of its own.

A reader per tree walks a packet as the model frames it and hands a handler a view of each
message: the handler declares an `on()` for each view it wants, and `on_unknown()` for a
code no message answers to.

Each protocol has its own directory, named for its identifier with the version as the last
segment — `Iex.IexEquities.Tops.IexTp.v1.64` becomes `iex/iexequities/tops/iextp/v1.64` —
matching the C++ namespace the code declares.

Within a protocol:

- `common/` — the byte codec, `Decimal`, the errors, how values print, and how a view reads text
- `enums/` — a scoped enum per coded field, with `to_string`
- `bitfields/` — a view per flag integer, a `bool` accessor per bit
- `structs/` — views of the packet, its frame, its headers and composites
- `messages/` — a view per message
- a reader per tree (`PacketReader.hpp`), and `definitions.hpp` including everything

Each library is compiled as `flyweight_<protocol>` by the repository's `CMakeLists.txt`, its
enumerations being the only sources a header-only view library has.
